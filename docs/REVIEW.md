# Review Policy

Projects enter as `experimental`.

The normal progression is:

    experimental -> developing -> candidate -> graduated

Graduation is a human decision.

Reviewers should consider:

- Does the published artifact actually work on MiSTer?
- Is the release reproducible?
- Are hardware requirements documented?
- Are known bugs and limitations documented?
- Is the license clear?
- Is AI assistance disclosed honestly?
- Is there a maintainer willing to support the project?
- Does the project belong in the experimental channel?

Passing automated validation does not imply that a project is endorsed,
stable, or safe for production use.
